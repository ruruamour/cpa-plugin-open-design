插件配置

插件可配置请求日志与额度暂停。额度暂停默认开启；CPA 原生界面的停用无法可靠归因，请优先通过本控制台启停。上游地址固定，代理池、路由和全局冷却由 CPA 宿主拥有。读取和保存都只在点击按钮时发生。

请求日志

未读取配置前这些控件不会发送请求；保存只提交日志相关字段。

额度暂停

开发中，请勿在生产启用。插件会将暂停状态投影到 CPA，并在本地拦截；到点后串行复查，只有新鲜官方结果确认有余量才解除，查询失败继续暂停。请确认 controlKey 与推理 key 属于同一账号，插件无法自动验证两者归属。

暂停期间请在本控制台启用/停用账户，不要使用 CPA 原生界面：原生入口和并发文件改写会直接写入同一份凭据文件，插件无法可靠区分一次停用是插件引发、宿主引发还是人工操作，两边同时改动可能让暂停与启用状态互相覆盖。未配置官方 controlKey（或缺少 Workspace ID）时无法自动复查额度，仍须人工处理。

CPA 自身的 402/403 冷却属于宿主，不会因插件解除暂停而提前结束；额度恢复后仍以 CPA 的实际调度结果为准。

宿主代理 / 路由（只读）

本插件没有私有代理池，也不提供代理、路由或全局冷却的增删改查。以下状态只用于说明边界。

插件可见状态

来自 GET /runtime；只显示插件可见状态，宿主拥有的调度、冷却和代理以 CPA 实际结果为准。

错误规则

作用范围：全部 OpenDesign 凭据。规则保存在插件中，并随每个账号的凭据同步给 CPA；实际的换号与冷却决定由 CPA 做出。

动作说明

停止

当前请求：停止重试和切换凭据，把错误返回客户端。

后续调度：不影响凭据的冷却状态。

停止并冷却

当前请求：停止重试和切换凭据，把错误返回客户端。

后续调度：把失败的凭据或模型暂时排除出调度。

继续

当前请求：继续尝试其他可用候选账号。

后续调度：不冷却失败的凭据。

继续并冷却

当前请求：继续尝试其他可用凭据。

后续调度：冷却期间跳过失败的凭据。

匹配方式

「包含文本」按子串匹配上游错误文本；「正则表达式」使用 Go 正则语法。状态码必须与上游返回的 HTTP 状态一致，两者都命中才会触发动作。

规则为空时

没有规则时不写入插件自有规则，改由 CPA 自身的配置决定分类与调度。
